# ReScan

Внутренний Telegram Mini App для последовательного учёта линз. React + Vite, Node.js/Express, Supabase Postgres, Tesseract.js, ExcelJS.

## Локальный запуск

Требуется Node.js 22.12+ (проверено на Node 24). В PowerShell используйте `npm.cmd`, если запуск npm.ps1 запрещён политикой Windows.

1. `npm install`
2. Скопируйте `.env.example` в `.env` и заполните переменные.
3. Примените `supabase/migrations/202611190001_rescan.sql` в SQL Editor нужного Supabase-проекта.
4. Для проверки в обычном браузере установите `DEV_AUTH=true` и `NODE_ENV=development`. Такой доступ разрешён только с loopback-интерфейса; не публикуйте dev-сервер и не используйте этот режим за прокси.
5. `npm run dev`, откройте `http://127.0.0.1:5173`.

Без настроенной базы интерфейс открывается, но показывает сообщение об отсутствии настройки. Данные не подменяются демонстрационными записями, сохранение не имитируется.

## Настройка сервера и Telegram

В `.env` задайте `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` (только на сервере), `TELEGRAM_BOT_TOKEN` и список никнеймов `ALLOWED_TELEGRAM_USERNAMES` через запятую (например `@ivan_petrov,@clinic_nurse`; регистр и `@` не важны). Часовой пояс клиники: `CLINIC_TIMEZONE=Europe/Moscow` по умолчанию. Пустой список сотрудников запрещает доступ всем.

1. `npm run build`.
2. Установите `NODE_ENV=production`, `DEV_AUTH=false` и выполните `npm start`. Сервер слушает `127.0.0.1:3001`; разместите его за HTTPS reverse proxy. UI и API должны иметь один origin. Передавайте заголовок `X-Telegram-Init-Data` без удаления прокси.
3. В @BotFather выберите бота → Bot Settings → Menu Button и укажите публичный HTTPS URL приложения. Сотрудник открывает кнопку меню в личном чате бота. Можно также отправлять inline-кнопку типа `web_app` с этим URL.
4. Укажите никнеймы (@username) сотрудников в серверном списке и перезапустите сервер. Проверьте открытие из Telegram на устройствах клиники.

Сервер проверяет HMAC подпись `initData`, срок 24 часа и список сотрудников. После истечения срока нужно заново открыть Mini App. Каждая сессия доступна только создавшему её сотруднику. Прямой доступ anon/authenticated к таблицам запрещён, RLS включён; сервер проверяет владельца перед каждым действием. Ключ service_role не передаётся в браузер. Не включайте логирование заголовков авторизации в прокси.

## Работа

Создайте новую сессию или выберите незавершённую. Сфотографируйте этикетку или загрузите JPEG/PNG/WebP. OCR выполняется в браузере, фотография не отправляется на сервер и не сохраняется в Supabase. Для первого запуска OCR нужен интернет: Tesseract загружает worker/WASM и английскую языковую модель. Этикетки с латинскими обозначениями поддерживаются; качество зависит от снимка. HEIC нужно предварительно преобразовать в JPEG.

Парсер ищет модель после MODEL/REF либо отдельный буквенно-цифровой код, силу рядом с D, серийный номер после SN/S N/S/N. Справочника нет, значения не подставляются. При нескольких кандидатах поле остаётся пустым. Штрихкоды не декодируются. Нестандартная разметка может потребовать ручного ввода: всегда сравнивайте все три поля с фотографией. Оригинальный текст OCR доступен под формой.

После «Добавить» запись подтверждается сервером. При ошибке фотография и поля остаются на экране; повторное нажатие использует тот же UUID и не дублирует запись. Одинаковый SN внутри сессии блокируется. Незавершённые сессии восстанавливаются из базы; неподтверждённая фотография после закрытия не сохраняется. Дата сканирования фиксируется сервером в момент подтверждения, хранится как timestamptz (UTC), не извлекается из этикетки.

Завершение блокирует дальнейшее добавление. XLSX повторяет форму Alcon «Consignment Order»: шапка с реквизитами клиники (переменные `CUSTOMER_NAME`, `CUSTOMER_EMAIL`, `CUSTOMER_CITY`, `CUSTOMER_SOLD_TO`, `CUSTOMER_SHIP_TO`; без них ячейки шапки пустые, на сервере их нужно задать), логотип и таблица Serial Number / Model / Diopter. SN — текст без пробелов с ведущими нулями; Diopter — сила, умноженная на 10 (8,5 D → 85). Даты сканирования в файле нет, она видна в приложении. Формулы из строк не исполняются. Выгрузка читает все строки с пагинацией, включая сессии больше 1000 записей. После сбоя загрузки завершённую сессию можно открыть и скачать повторно. В списке показываются последние 100 сессий сотрудника.

Браузерное скачивание выполняется через Blob и ссылку .xlsx. Поддержка сохранения зависит от Telegram WebView/ОС; для устройств с Web Share API доступна кнопка «Сохранить / поделиться». Перед вводом в эксплуатацию проверьте скачивание в используемых клиентах Android/iOS/Desktop.

## Проверки

`npm test` — разбор OCR, ввод силы, часовые пояса, реальный XLSX с обратным чтением, подписи Telegram и запрет доступа.

`npm run build` — production-сборка.

`npx playwright test` — 6 браузерных проверок на мобильном и настольном размерах: создание сессии, проверка/исправление полей, повтор после ошибки связи, возобновление, экспорт и отсутствие конфигурации. API и результат OCR в этих тестах явно подменены: они проверяют пользовательский сценарий, а не реальную базу или качество распознавания. Для первого запуска нужен `npx playwright install chromium`.

Перед эксплуатацией: примените миграцию в тестовом проекте, выполните полный цикл на реальных этикетках, проверьте возобновление сессии на другом устройстве того же сотрудника, запрет доступа другому сотруднику и отсутствие потери записей при разрыве сети. Автоматические проверки не заменяют оценку OCR на фотографиях клиники.

Документация: [Telegram initData](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app), [Tesseract.js](https://github.com/naptha/tesseract.js), [Supabase JS](https://supabase.com/docs/reference/javascript/initializing).
